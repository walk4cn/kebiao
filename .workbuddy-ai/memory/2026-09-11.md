## 在本机从零搭建 Android APK 打包环境并跑通构建

原 `build-apk.sh` 硬编码了上一台电脑的路径（`C:\Users\Lenovo\...`），本机用户名 suda，全部失效。

**安装的工具链**（统一放在无空格路径 `C:\Users\suda\.workbuddy-ai\binaries\android`）：
- JDK：Temurin 17.0.20.1（清华 Adoptium 镜像）→ `jdk-17`
- Android SDK：cmdline-tools latest + platform-tools + platforms;android-36 + build-tools;36.0.0 → `sdk`
- Gradle 8.7（腾讯镜像 `mirrors.cloud.tencent.com/gradle`）→ `gradle-8.7`
- 构建工程：`C:\Users\suda\.workbuddy\projects\kebiao-apk`
- 签名：`kebiao.jks`（alias kebiao / 密码 kebiao2026），新生成

**改写 build-apk.sh 为可移植版**：路径由 `$HOME` 推导，可用 `ANDROID_TOOLS` / `APK_PROJ` 覆盖；
自动同步 android/ 工程、缺签名则生成、写 local.properties、构建、拷回 `课表.apk`。
`KB_OFFLINE=1` 可离线构建。README 第四节同步更新。

**踩过的坑**：
1. `gradle.bat` / `keytool.exe` / `apksigner.bat` 是 Windows 程序，必须给 `C:\...` 路径；
   Git Bash 的 `/c/...` 会被当成无效目录（报 JAVA_HOME invalid / FileNotFoundException）。
   脚本里用 `cygpath -w` 转换导出给它们，bash 内部自检仍用 POSIX 路径。
2. `sdkmanager` 下载时进度不可见（`.temp` 里才看得到），容易误判成卡死——实际 dl.google.com 很快。
   国内没有可用的 Android SDK 镜像（腾讯 AndroidSDK 400、清华 404），无需切换；
   Maven 依赖走阿里云已在 build.gradle/settings.gradle 里配好。
3. 代理：环境有 `http_proxy=127.0.0.1:57075`，但实测直连 maven.aliyun.com / dl.google.com 都通，
   Gradle 不需要额外配代理。
4. 沙箱下 `find $HOME -maxdepth 4` 会因触碰 `.ssh` 被拒，搜索要限定目录。

**重要遗留问题**：旧 APK 是用旧电脑上的 `kebiao.jks`（DN: CN=Kebiao, OU=Study, L=WH, ST=HB）签的，
该文件不入库且未带过来，本机已换新密钥（OU=App）。**手机上需先卸载旧版才能安装新包**。
若想保留覆盖升级，需从旧电脑拷贝 `kebiao.jks` 覆盖到构建工程目录。
